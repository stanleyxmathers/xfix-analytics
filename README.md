# XFIX Service Center Analytics

Система аналитики для сервисного центра Apple и Яндекс на базе n8n + PostgreSQL.

## Структура проекта

```
├── schema.sql          # PostgreSQL схема (8 таблиц + 3 вьюшки)
├── dashboard.html      # HTML-дашборд (открыть в браузере)
└── README.md
```

## Архитектура

```
Excel (.xlsx) → n8n Import Workflow → PostgreSQL
                                           ↓
HTML Dashboard ← n8n API Workflow ← PostgreSQL
```

**n8n workflows (созданы в imtime.app.n8n.cloud):**
- `XFIX Analytics — Import Report` (ID: HMRjNqV2LU30cTCx) — загрузка Excel
- `XFIX Analytics — API` (ID: 1abNZNFHGYPeFRfh) — данные для дашборда

## Первичная настройка

### 1. PostgreSQL — создать БД и схему

```bash
psql -U postgres -c "CREATE DATABASE xfix_analytics;"
psql -U postgres -d xfix_analytics -f schema.sql
```

### 2. n8n — добавить credential для PostgreSQL

1. Открыть [imtime.app.n8n.cloud](https://imtime.app.n8n.cloud)
2. Перейти: **Credentials → New Credential → Postgres**
3. Заполнить:
   - **Host**: ваш PostgreSQL хост
   - **Port**: 5432
   - **Database**: xfix_analytics
   - **User / Password**: ваши данные
4. Нажать **Save**

### 3. Привязать credential к нодам

В каждом workflow открыть ноды Postgres и выбрать созданный credential:

**XFIX Analytics — Import Report** — 7 нодов Postgres:
- Insert Upload
- Insert Actions
- Update Base Costs
- Insert Services
- Insert Stats
- Insert Anomalies
- Insert Insights

**XFIX Analytics — API** — 1 нода Postgres:
- Query DB

### 4. Активировать workflows

После привязки credentials нажать **Activate** в обоих workflow.

Webhook URLs после активации:
- Import: `https://imtime.app.n8n.cloud/webhook/import-report`
- API:    `https://imtime.app.n8n.cloud/webhook/api`

## Загрузка первого отчёта

### Через дашборд
1. Открыть `dashboard.html` в браузере
2. Перейти в **Настройки** → проверить URL n8n
3. Нажать **"Загрузить отчёт"** в верхней панели
4. Перетащить или выбрать Excel файл

### Через curl (тест)
```bash
curl -X POST https://imtime.app.n8n.cloud/webhook/import-report \
  -F "data=@Report_23.6.2026_13.34.13.xlsx"
```

## Формат входного Excel файла

Файл экспортируется из внутренней системы. Одна строка = одно действие мастера.

| Колонка | Поле | Описание |
|---------|------|----------|
| A | id | ID действия |
| B | ФИО | Имя сотрудника |
| C | дата | Дата действия (Excel serial или дата) |
| E | Офис | Офис |
| F | Отдел | Отдел |
| G | Тип | Тип действия |
| H | Группа | Группа/устройство |
| I | Подгруппа | Подгруппа |
| J | Комментарий | Комментарий |
| K | price | Стоимость, ₽ |
| X | id сервис | ID обращения (несколько строк на одно обращение) |
| AK | Вендор | Apple / Яндекс |

> Если заголовки столбцов в Excel называются буквами (A, B, C...), система распознаёт их автоматически. Поддерживается и формат с русскими заголовками.

## Логика аналитики

### Зоны обращений
| Зона | Условие | Маркировка |
|------|---------|------------|
| Норма | стоимость ≤ базовой | ✓ |
| Повышен | стоимость > базовой × 1.3 | 🟡 |
| Критично | стоимость > базовой × 2 | 🔴 |

### Самообучающаяся модель базовых стоимостей
После каждой загрузки система автоматически:
1. Вычисляет медианную стоимость по каждой комбинации `вендор + группа`
2. Определяет наиболее частый набор действий (базовый комбо)
3. Обновляет таблицу `base_costs`

Чем больше исторических данных, тем точнее модель.

### Аномалии сотрудников
Срабатывают при:
- Средняя стоимость обращения **> 120%** от средней по отделу → предупреждение
- Средняя стоимость обращения **> 150%** от средней по отделу → критично
- Общий перерасход **> 130%** от среднего по отделу → предупреждение
- Общий перерасход **> 200%** от среднего по отделу → критично

### Инсайты WoW
Генерируются автоматически при изменении показателей **> 5%** неделя к неделе:
- Количество обращений
- Сумма выплат
- Перерасход
- Средняя стоимость обращения

## Обновление данных (еженедельно)

## Устранение проблем

**Дашборд не загружает данные:**
- Проверить URL n8n в Настройках дашборда
- Убедиться что workflows активированы
- Проверить консоль браузера (F12)

**Ошибка при загрузке Excel:**
- Проверить credential PostgreSQL в n8n
- Убедиться что схема применена к БД
- Посмотреть логи в n8n (Executions)

**Базовые стоимости = 0:**
- Нормально при первой загрузке
- После 2+ загрузок модель начнёт обучаться
- Минимум 2 обращения на комбинацию вендор+группа для расчёта

**Нет инсайтов:**
- Инсайты генерируются со второй загрузки (нужна предыдущая неделя для сравнения)
- Порог: изменение > 5% (настраивается в коде)
