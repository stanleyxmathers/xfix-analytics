# Выгрузка очереди из FileMaker для «Планирования»

Раз в неделю (понедельник) и каждое утро выгружаем технику в работе в Excel и
загружаем в дашборд: **Планирование → Проверка недели → «Загрузить технику в работе»**.
Дашборд сам узнаёт выгрузку FileMaker по названиям колонок, раскладывает устройства
по задачам по статусу и подставляет очередь в «Проверку недели» и «План смены».

Поля взяты из структуры базы (выгрузка 01.10, таблица `Service::Service`).

## 1. Макет «XFIX выгрузка» (один раз)

1. **Макеты → Управление макетами → Новый**: таблица/вхождение **Service**, тип — «Таблица»
   (список), название `XFIX выгрузка`.
2. Добавить на макет поля ниже. Порядок на макете не важен — порядок задаёт экспорт.
3. Макет можно скрыть из меню: им пользуется только скрипт.

## 2. Поля выгрузки (порядок экспорта)

| № | Поле `Service::` | Зачем |
|---|---|---|
| 1 | `id` | номер карточки |
| 2 | `id service` | связь с выгрузкой действий: это поле «id сервис» |
| 3 | `Статус` | какая задача сейчас у устройства |
| 4 | `Этап` | для проверки разметки статусов |
| 5 | `Дата время последней смены статуса` | сколько уже в статусе |
| 6 | `Дата время завершения этапа в текущем статусе` | **срок в статусе** — главный срок |
| 7 | `Осталось времени до истечения срока в статусе` | запасной вариант срока |
| 8 | `Дата время получения техники` | дата приёма |
| 9 | `Вендор` | Apple / Яндекс |
| 10 | `Тип устройства` | группа для норм (iPhone, AirPods…) |
| 11 | `Наименование техники` | если тип не распознан |
| 12 | `Тип ремонта` | гарантия / платный |
| 13 | `Ключ экспресс согласован` | экспресс (1 — да) |
| 14 | `Дата окончания план` | согласованная дата экспресса — см. вопрос ниже |
| 15 | `Высокий приоритет` | ручной приоритет |
| 16 | `Сети дата истечения клиентского срока` | 45 дней |
| 17 | `Доставка тип по направлению` | как отдаём клиенту |
| 18 | `Связь доставка Выдать` | непусто — выдача через доставку (ТК) |
| 19 | `Аутсорс партнёр` | куда уходит в АСЦ |
| 20 | `Ответственный ИОФ` | кто ведёт |
| 21 | `Дата время модификации` | контроль свежести |

Колонки дашборд ищет по названиям — переименовывать поля в выгрузке нельзя, порядок
может быть любым. Лишние колонки не мешают.

## 3. Скрипт «XFIX выгрузка очереди»

**Быстрый путь (macOS, без создания макета):** в терминале из папки проекта

```bash
bash filemaker/fm_export_snippet.sh
```

— шаги скрипта окажутся в буфере обмена; в рабочем пространстве скриптов создать новый
скрипт и вставить (Cmd+V). Скрипт запускается с любого макета карточек сервиса (таблица
Service): поля для поиска берёт по имени таблицы макета, экспорт — из полей таблицы, а не
макета. Останется один раз настроить шаг «Экспортировать записи» (см. ниже).

Ниже — те же шаги текстом, если вставка не сработала.

**Скрипты → Рабочее пространство скриптов → Новый скрипт**, шаги:

```
Установить захват ошибок [ Вкл ]
Установить переменную [ $layout ; Значение: Get ( НазваниеМакета ) ]
Перейти к макету [ «XFIX выгрузка» (Service) ; Анимация: Нет ]

# Статусы техники в работе — поправьте под точные названия в базе
Установить переменную [ $statuses ; Значение:
    List ( "Доставка" ; "Ожидаем получения" ; "В работе" ; "Диагностика" ;
           "На согласование" ; "На осмотр внутри" ; "К заказу" ;
           "Определение стратегии обслуживания" ; "На отправку" ;
           "Проверка после ЗАСЦ" ; "Проверка" ; "К выдаче" ) ]

Войти в режим поиска [ Пауза: Выкл ]
Установить переменную [ $i ; Значение: 1 ]
Цикл
    Задать поле [ Service::Статус ; "==" & GetValue ( $statuses ; $i ) ]
    Установить переменную [ $i ; Значение: $i + 1 ]
    Выйти из цикла, если [ $i > ValueCount ( $statuses ) ]
    Новая запись/запрос
Конец цикла
Выполнить поиск [ ]

Если [ Get ( КоличествоНайденныхЗаписей ) = 0 ]
    Показать пользовательское диалоговое окно [ "Выгрузка" ; "Не найдено ни одной карточки в этих статусах" ]
    Перейти к макету [ $layout ]
    Выйти из скрипта [ ]
Конец если

Установить переменную [ $ts ; Значение: Get ( ТекущаяМеткаВремени ) ]
Установить переменную [ $name ; Значение:
    "xfix_queue_" & Year ( $ts ) & Right ( "0" & Month ( $ts ) ; 2 ) & Right ( "0" & Day ( $ts ) ; 2 )
    & "_" & Right ( "0" & Hour ( $ts ) ; 2 ) & Right ( "0" & Minute ( $ts ) ; 2 ) & ".xlsx" ]
Установить переменную [ $path ; Значение: "file:" & Get ( ПутьКРабочемуСтолу ) & $name ]

Экспортировать записи [ С диалогом: Выкл ; «$path» ; Excel ]
Перейти к макету [ $layout ]
Показать пользовательское диалоговое окно [ "Выгрузка" ; "Сохранено на рабочий стол: " & $name
    & ¶ & Get ( КоличествоНайденныхЗаписей ) & " устройств" ]
```

В английском интерфейсе шаги называются `Set Error Capture`, `Go to Layout`, `Enter Find Mode`,
`Set Field`, `New Record/Request`, `Perform Find`, `Export Records`, функции —
`Get ( LayoutName )`, `Get ( FoundCount )`, `Get ( CurrentTimestamp )`, `Get ( DesktopPath )`.

**Настройка шага «Экспортировать записи»** (один раз, при создании скрипта):
1. Открыть параметры шага → «Указать выходной файл»: тип **Excel (.xlsx)**, путь — `$path`.
2. «Указать порядок экспорта»: добавить 21 поле из таблицы выше, группировки нет.
3. В параметрах Excel отметить **«Использовать имена полей как имена столбцов в первой строке»** — без этого
   дашборд не узнает колонки.

Если нужен отбор не по статусам, а по готовому сохранённому поиску (например,
«общ фильтр в работе»), замените блок поиска на `Выполнить поиск [ Восстановить ]`
с этим запросом — колонки останутся те же.

## 4. Расписание

- **Понедельник утром** — выгрузка и «Проверка недели»: хватит ли смен на неделю.
- **Каждое утро** — новая выгрузка, затем «План смены» на сегодня: очередь, сроки,
  кто на какой роли. Снимок хранится в браузере, следующая загрузка его заменяет.

## Вопросы по полям (уточнить до первой выгрузки)

1. ✅ «id сервис» в выгрузке действий — `Service::id service`.
2. Где согласованная дата экспресса: `Дата окончания план`, `Ориент дата фикс` или другое поле?
3. Как различить выдачу самовывозом и через ТК: `Связь доставка Выдать` непусто — значит ТК?
4. ✅ Пока устройство в АСЦ, статус — «Аутсорс» + код страны («Аутсорс КЗ»). Для плана смены
   это ожидание; в выгрузку можно не включать.
5. Командировки — в отдельном инструменте, не в FileMaker. План: API между инструментом
   командировок и дашбордом (дата, направление, кто едет, список техники).
